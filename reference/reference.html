the four concepts

Concept Main responsibility Example
Features Organize code by functionality / business domain appointments/
Services Perform operations + business logic (may call DB or external providers) emailService.js
Utils Small, general reusable helper functions formatDate.js
Middlewares Process HTTP requests and responses protect.js
How they work together — a receptionist books an appointment: Feature (appointments) organizes the flow → Middleware (protect/restrictTo) checks auth + permissions → Service (appointmentService checks availability and creates the appointment) → Utils (formatDate/calculateAge) when needed. Overlap is allowed — services may live at features/appointments/services/, and utils may be feature-specific or shared. The goal is a clear responsibility per file, not one mandatory layout.
Location What goes inside What does NOT
server/controllers Request handlers (auth, user, appointment…) Database schema, route definitions
server/routes Only endpoint paths + middleware order (thin) Business logic
server/services Business-logic operations; may use DB or external providers Request handlers, route definitions
server/models Mongoose schemas + methods/hooks API/response logic
server/middleware Cross-cutting: auth, roles, errors, rate limit Route-specific handlers
server/utils Small reusable helpers (formatCurrency, paginate, apiResponse) Business logic
client/features Page UI + slice + api file for one domain (e.g. appointments) Global store config, shared UI
client/pages Route-level screens (compose components) Reusable primitives
client/components Shared, reusable UI Store wiring / one-page logic
client/app Store factory only Feature slices

18. TypeScript Setup + Commands

Two supported setups. Pick the one that matches the project — the tsconfig.json files differ on purpose. Both use moduleResolution: "bundler" (so relative imports carry no .js extension). Type A (Node) uses require / module.exports; Type B (Vite) uses import / export.

Project Type A — Node.js / Express (CommonJS)

install (copy-paste, no comments):

npm init -y
npm i -D typescript tsx @types/node
npm i express
npm i -D @types/express
npx tsc --init
# 1. initialize package.json
npm init -y

# 2. dev dependencies (TypeScript compiler + tsx runner + Node types)
npm i -D typescript tsx @types/node

# 3. only if it is an Express API — Express itself + its types
npm i express
npm i -D @types/express
// package.json — the TypeScript-relevant fields
{
  "type": "commonjs",
  "main": "dist/index.js",               //production entery point
   "scripts": {
    "dev": "tsx watch src/index.ts",     // Dev: run .ts + auto-reload
    "build": "tsc",                      // Build: .ts → .js into dist/
    "start": "node dist/index.js",       // Start: run compiled JS
    "typecheck": "tsc --noEmit"          // Check types only, no output
  }
    
}

type: "commonjs" tells Node to treat this folder's .js output as CommonJS. Combined with the Node types below, you can write plain require and module.exports in your .ts files — no import / export needed. 

// tsconfig.json — Node.js compilerOptions
"lib": ["esnext"],
"types": ["node"]

// install the Node types once
npm install -D @types/node
// src/index.ts — require / module.exports
const { fun3 } = require('./newFile');

module.exports = { fun3 };

// tsconfig.json (server — exact)
{
  "compilerOptions": {
    "lib": ["esnext"],
    "target": "es2022",
    "module": "commonjs",
    "moduleResolution": "bundler",
    "outDir": "./dist",
    "rootDir": "./src",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "resolveJsonModule": true,
    "forceConsistentCasingInFileNames": true,
    "sourceMap": true,
    "declaration": true,
    "types": ["node"]
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}
server/
├── src/
│   └── index.ts
├── package.json
└── tsconfig.json
Type A rules (Node.js): use require and module.exports. The Node types ("types": ["node"] + npm i -D @types/node) give full typing and autocomplete for them. No file extensions: require('./file'). Keep moduleResolution: "bundler" — do not switch to nodenext / node16 (that forces .js extensions). 
// src/index.ts
const express = require('express');

const app = express();
const PORT = Number(process.env.PORT) || 3000;

app.get('/api/health', (_req, res) => {
  res.json({ ok: true });
});

app.listen(PORT, () => console.log(`API on ${PORT}`));

module.exports = app;

typing req.user (declaration merging)

// src/types/express.d.ts
import { Request } from 'express';

declare global {
  namespace Express {
    interface Request {
      user?: {
        _id: string;
        name: string;
        email: string;
        role: 'user' | 'admin';
      } | null;
    }
  }
}

export {};

Plain Node.js — no Express (Type A variant)

install (copy-paste, no comments):

npm init -y
npm i -D typescript tsx @types/node
npx tsc --init
// tsconfig.json (plain Node — no Express)
{
  "compilerOptions": {
    "lib": ["esnext"],
    "types": ["node"],
    "target": "es2022",
    "module": "commonjs",
    "moduleResolution": "bundler",
    "outDir": "./dist",
    "rootDir": "./src",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "resolveJsonModule": true
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}
// package.json scripts (plain Node)
{
  "type": "commonjs",
  "main": "dist/index.js",
  "scripts": {
    "dev": "tsx watch src/index.ts",
    "build": "tsc",
    "start": "node dist/index.js",
    "typecheck": "tsc --noEmit"
  }
}
// src/index.ts — Node built-ins only (http, fs, path, os...)
const http = require('http');

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain' });
  res.end('Hello from plain Node.js');
});

server.listen(3000, () => console.log('API on 3000'));

module.exports = server;
No Express? This is Type A minus express and @types/express. Only @types/node is needed. Everything else is identical: CommonJS output, require / module.exports, and the same tsconfig.json keys (lib / types / moduleResolution).

Project Type B — Vite (React / Vue / vanilla TS)

install (copy-paste, no comments):

npm create vite@latest my-app -- --template react-ts
cd my-app
npm install
npm i -D @types/node
npx tsc --init
# create + install
npm create vite@latest my-app -- --template react-ts
cd my-app && npm install

# create into the CURRENT folder (no nested my-app/)
npm create vite@latest . -- --template react-ts

# Node types are needed for vite.config.ts only — NOT for src/ code
npm i -D @types/node
// tsconfig.json (browser code — do NOT add "node" to types)
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "resolveJsonModule": true,
    "isolatedModules": true,
    "noEmit": true,
    "lib": ["ES2022", "DOM", "DOM.Iterable"]
  },
  "include": ["src"]
}
// tsconfig.node.json (for vite.config.ts only — scope Node types here)
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "skipLibCheck": true,
    "types": ["node"]
  },
  "include": ["vite.config.ts"]
}
Type B import rules: no file extensions on imports (bundler resolution). Use import.meta.env.VITE_* for env vars — not process.env. Do not use fs, path, or other Node APIs inside src/ code. The react-ts template ships src/main.tsx + src/App.tsx; components live in .tsx, plain logic/helpers in .ts.

verify the setup

# Type A
npm run start       # tsx watch src/index.ts
npm run typecheck   # tsc --noEmit

# Type B
npm run dev         # vite dev server with HMR
npm run build       # tsc -b && vite build → type-checks THEN bundles
npx tsc --noEmit    # type-check only (CI-safe)

25. Git & GitHub

configure once

git config --global user.name "Your Name"
git config --global user.email you@example.com
git config --global init.defaultBranch main
git config --global core.editor code --wait

daily loop

git status
git add .
git commit -m "feat: add login"
git pull --rebase              # before pushing
git push -u origin main

branches

git branch                    # list
git checkout -b feature/x     # create + switch
git switch main
git merge feature/x
git branch -d feature/x       # safe delete

history & undo

git log --oneline --graph --decorate
git diff
git stash && git stash pop
git reset --soft HEAD~1       # undo commit, keep changes staged
git reset --hard HEAD~1       # DISCARD commit + changes (dangerous)
git revert <sha>              # safe inverse commit

git restore file.txt          # discard uncommitted changes to a file

remotes & tags

git remote add origin git@github.com:user/repo.git
git remote -v
git tag v1.0.0
git push origin --tags

pull request flow

git checkout -b feature/x
git add . && git commit -m "feat: x"
git push -u origin feature/x
# open the PR link Git prints, or via CLI:
gh pr create --title "x" --body "what & why"

GitHub CLI (gh)

gh auth login
gh repo create myapp --public --source . --remote origin --push
gh pr create / gh pr list / gh pr merge / gh pr checkout
gh issue create / gh issue list
gh run list / gh run watch      # CI pipelines
